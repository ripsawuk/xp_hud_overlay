## The tab structure

| Tab | Rows |
|---|---|
| General | `Operator XP HUD v10`, `Reset everything`, `Close` |
| XP Bar | `Bar length <1000>`, `Bar: ON`, `Colour: GREEN`, `Look: DEFAULT`, `Position: BOTTOM`, `Reset bar` |
| XP Text | `Text: ON`, `Prestige: ON`, `Size: 11`, `Position: CENTER`, `Reset text` |
| XP Popup | `Popup: ON`, `Colour: AUTO`, `Position: CENTER`, `Reset popup` |

Each reset restores only its own tab from `CONFIG` (`ResetBar`/`ResetText`/`ResetPopup`); `Reset everything` is the
old whole-table reset. `Look` is a placeholder with one option: the row works and the value is stored and logged, but
the drawing is still one look.

## The popup's position rules

`placeTracker`, with `ls`/`le` the label's ink start/end and `half = width/2`:

    text left   + popup left    -> left of the text; no room -> flips to the text's right
    text center + popup center  -> left of the text
    text right  + popup right   -> right of the text
    any         + other slot    -> that region: -half, -150/2, half-150
    always clamped to [-half, half - 150]

The literal reading of the four rules puts the popup outside the bar when the text is already at the edge; "so it
stays within the bar constraints" is what makes it flip instead. That interpretation is the one thing launch 5 should
look at first.

## Live changes without a rebuild

- size: `styledRow.setSize` -> `SetFontSize`/`SetMinFontSize` on the element already drawing; the band (14..32) does
  not move.
- alignment: `setAlign` -> `SetAlignment` (engine face) or a re-layout (PNG face).
- prestige: `labelFor(m, not CFG.showPrestige)` recomputed on repaint.
- popup colour: `popupColours()` (`auto` = the bar's accent/shadow).
- bar off/on: `setFill` refuses to draw while `CFG.showBar` is false, so an XP change cannot resurrect the fill.

## Persistence - not done

The settings do not survive a restart. There is no store this mod has evidence it may write: `verify.py` bans every
setter, the loader has no `io`, and `players\progression.*` belongs to Kronos. v10 logs what the VM offers:

    [ZmXpHud] storage: FileStorage (table), ...

That line (from `CONFIG.debug`) decides the next build: a file API if one of `FileStorage`, `Storage`, `storagefile`,
`PlayerData`, `GAMERPROFILE`, `DvarUtils` has a writer, otherwise a probe to see whether a custom dvar name is archived
across restarts. Until a restart proves it, no claim of persistence.
