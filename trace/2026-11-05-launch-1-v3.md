## Why the row was missing - the leading hypothesis

The hook matched `widget.id == "zmpausemenubuttons"` inside the wrapped `MenuBuilder.BuildRegisteredType`. Three
ways that can miss, and the v3 paste cannot tell them apart:

1. the panel is built by a path that does not call this VM's `MenuBuilder.BuildRegisteredType`;
2. it does, but the widget carries a different id in v1.41;
3. the wrapper is not in the call chain in the VM that builds menus (another loader captured the function first).

The dump says the ZM pause list *is* `zmpausemenubuttons`, registered by that name and built with
`menuBuilder.BuildRegisteredType("zmpausemenubuttons", ...)`:
`ui\generated\widgets\ingame\zm\zmpausemenubuttons.dec.lua:228-236, 555` and
`ui\generated\widgets\sat\globalpanelnavigation.dec.lua:361-367`. Its buttons include the ones in the screenshot
(Achievements, Social, Quit to desktop, Leave game, `SAVELOAD.saveandquit`), so it is the same widget.

Since the hypothesis could not be chosen from the paste, v4 settles it with evidence instead of a guess: a bounded
log of every build the hook sees, plus two hooks that do not depend on the id.

## v4 - what changed

| Change | Why |
|---|---|
| `pause hook armed (n)` at load | says whether `MenuBuilder.registerType` / `GetConstructorForType` were reachable in that VM at all |
| the registered constructor of `zmpausemenubuttons` / `mppausemenubuttons` is wrapped | appends the row whatever builds the panel, and without matching an id |
| `MenuBuilder.registerType` is wrapped for those two names | catches the case where the panel's file loads after this script |
| `build <type> id=<id>`, first 40 distinct, `CONFIG.debug` | if no line appears at all, the wrapper is not in the chain (hypothesis 3); if lines appear without a pause entry, the id differs (hypothesis 2) |
| the row's own `genericbutton` build is fenced (`S.addingRow`) | the constructor hook fires for the button too; without the fence the row build could recurse |

`<path>` is `build hook`, `constructor hook` or `register hook` - that names which of the three worked.

If there are **no** `build` lines at all, the wrapper is not in the chain in the VM that draws menus, and the next
step is a hook that does not use `MenuBuilder` (the FlowManager stack, or `GLOBAL_PANEL`).
