# trace - 2026-11-05 - v11: the five bugs from the v10 launch

v10 ran; the user reported five defects. Each one traced to a mechanism, not a preference.

| Report | Cause | Fix |
|---|---|---|
| "Pressing reset here doesnt reset the bar size, it only does it visually" | `CFG.width` was reset, but `GenericArrowButton` holds its own `_currentValue`, and its `action` feeds `SetWidth` from **that** value - so the row still read 200/1200 and the next press jumped back | `syncArrow()` calls `SetCurrentValue` with the file's length after `ResetBar` / `Reset everything` |
| "Changing size, position doesnt do anything to the text straight away ... only adjusts the slight coloured hue" | `SetFontSize` / `SetAlignment` alone do not re-lay a styled row in this client; only `setText` does | `row.setSize` / `row.setAlign` re-set the same string (`row.str = nil; row.set(s, rgb)`) |
| "Messing with the positioning of the text doesnt take the coloured hue behind it" | `fitGlow` was centred on `0` (the bar's middle) whatever the alignment | it centres on the label's position for LEFT / CENTER / RIGHT |
| "the XP popup can overlap the XP Text" | placement used a measured width that lags a frame after a size change, and nothing compared the two spans | `placeTracker` checks the label's span and takes the free side; size/position changes schedule one deferred repaint so the measurement settles |
| "Pressing esc closes the menu, but the game still thinks its in the pause menu" | the callback closed our page and the event carried on to the pause menu underneath, which then unpaused the game | the callbacks `return true`: `AddGamepadEventCallback` stops propagation when the callback does (`ui\luielement.dec.lua:328-329`) |
